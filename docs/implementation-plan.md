# 実装計画

## 技術構成
- React 19 + TypeScript 5.9 + Vite（ビルド）+ Vitest（テスト）
- 依存は最小限（実行時は react / react-dom のみ）。外部API・ログイン・解析なし
- 素のJS版（初版プロトタイプ）から計算式・解説文・デザインを移植した（初版はこの公開リポジトリには含めていない）

## 構成
```
src/config/      設定データ（難易度・商品・費用・目標値）
src/engine/      計算ロジック（DOM非依存）：乱数、端数処理、需要、週次シミュレーション、整合性チェック
src/learning/    学習：用語集、予想問題、解説文生成、費用の性質と損益分岐点、最終テスト、評価
src/save/        セーブデータの保存・検証・復元（判断の履歴からシードで再計算）
src/ui/          React コンポーネントとスタイル
tests/           Vitest（会計・在庫・資金・セーブ検証・5年間の進行・解説と数字の一致・バランス）
scripts/         バランス集計、ヘッドレスChromeでの通しプレイ確認
```

## 進め方（順番）— すべて完了（2026-10-17、詳細は progress.md）
1. 会計・在庫・需要の計算ロジック（四半期の中を週次で計算し、鮮度と期末在庫を矛盾させない）
2. 計算の整合性テスト（PL・在庫の数量と金額・資金・二重計上・再現性）
3. イージーで5年間遊べる画面
4. 学習解説と振り返り（解説の数字は計算結果から生成し、テストで一致を確認）
5. ふつう・むずかしい（広告、季節、できごと、冷蔵設備、借入）
6. セーブ（検証つき）とスマートフォン対応
7. 難易度バランス確認（「予測に合わせる」だけのプレイと工夫したプレイを同じ乱数で比較）

## 移行で変わる主な点（プロトタイプとの差）
- 期末に売れ残りの一定割合を廃棄 → **週ごとの入荷ロットと賞味期限（週）**で、売れ残り・廃棄・持ち越しを計算
- 「販管費＝固定費、売上原価＝変動費」の一般化をやめ、費目ごとに費用の性質を定義（`docs/accounting-rules.md`）
- 資金は週ごとに計算し、期中に一度でもマイナスになれば資金ショート
- セーブは結果ではなく「判断の履歴」を保存し、読み込み時に検証してから再計算
