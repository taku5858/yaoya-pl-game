# セキュリティと安全対策

## 前提（初期版）
- ログイン、個人情報の収集、外部API、アクセス解析、広告配信は**なし**。通信は静的ファイルの読み込みだけ。
- ランキングやサーバーへのスコア送信はない。ローカル保存のスコアは**本人が改変できる前提**で、複雑な不正対策はしない。
- 環境変数・APIキーは不要（`.env.example` にその旨のみ記載）。

## セーブデータ（`src/save/saveData.ts`）
- 保存先：ブラウザの `localStorage`、キー `yaoya-pl-save-v2`（読み込めなかったデータの退避先は `yaoya-pl-save-v2-backup`）。
- 保存する内容：アプリ識別子、バージョン、保存日時、シード、難易度、各ターンの判断と予想の選択、進行段階、入力中の判断、理解度テストの回答。**個人情報・秘密情報は入れない**（テストで保存項目を固定）。
- 結果・スコア・資金は保存せず、読み込み時に**シードと判断の履歴から再計算**する。数値を書き換えてもそのまま反映されない。
- 読み込み時の検証：
  - 文字数の上限（200,000文字）、JSONとして読めるか、オブジェクトか
  - アプリ識別子、バージョン（2のみ）、難易度（既知の値のみ）、シード（英数字・`_`・`-` の20文字まで）
  - ターン数（20以下）、各ターンの判断がオブジェクトか、予想の問題IDと選択肢が実在するか
  - 判断の数値は `normalizeDecisions` で型と範囲を検証し、範囲内に直す（負の仕入れ、NaN、文字列、範囲外、使えない機能を無効化）
  - 進行段階の矛盾（20ターン前なのに終了など）は安全な段階に直す
  - 資金ショートになる記録があれば、その手前で止める
- 壊れたデータでも例外で画面全体を止めない。タイトルで理由を表示し、**データは消さない**。新しく始めるときは、退避キーにコピーしてから上書きする。
- `localStorage` が使えない環境（プライベートモード等）でも例外を出さず、保存できない旨を表示して遊べる。
- 予期しない表示エラーは React のエラー境界で受け止め、「再読み込み」か「セーブを退避して新しく始める」を本人が選べる。

## 入力値
- 価格・仕入れ数・人員・広告・借入・返済は、UI のボタンで範囲内に制限し、さらに計算前に `normalizeDecisions` で必ず検証する（UI を経由しない値も防ぐ）。
- 仕入れ数の入力欄は数字以外を受け付けず、確定時に10個単位・0〜9,990個に直す。
- シード入力は英数字・`_`・`-` だけを残す。URL パラメータ（`seed`・`difficulty`）も同じ検証を通す。
- 予想の選択は、その問題の選択肢にある値だけを受け付ける。

## 画面表示
- React の通常の描画のみを使い、`dangerouslySetInnerHTML` や `innerHTML` は使わない（ユーザー入力やセーブ内容を HTML として挿入しない）。
- 外部スクリプト・外部フォント・CDN を読み込まない。

## 依存パッケージ
- 実行時の依存は `react` と `react-dom` のみ。開発時は TypeScript、Vite、Vitest、型定義、vite-node。
- `package-lock.json` を保存し、バージョンを固定する。`npm audit` の結果は `docs/progress.md` に記録する。

## 秘密情報
- コード・ログ・Git に秘密情報を入れない。`.env` 系ファイルは `.gitignore` で除外（`.env.example` のみ管理）。
- フロントエンドに API キー等を埋め込まない（そもそも不要）。

## 公開（GitHub Pages）
公開は外部への公開にあたるため、実施前に必要性を説明して確認をとる。
- 公開先：GitHub Pages（`.github/workflows/pages.yml`、公式の Pages 用 Actions）。公開用リポジトリ `taku5858/yaoya-pl-game` から公開する。公開URL `https://taku5858.github.io/yaoya-pl-game/`
- 公開範囲：公開サイトは URL を知っている人なら誰でも閲覧でき、検索エンジンに載る可能性もある（リポジトリが非公開でも、有料プランの Pages サイトは原則として公開される）。
- ワークフローの安全対策：`push`（main）と手動実行でだけ起動し、`pull_request` では起動しない。`push` ではチェックとビルドだけを行い、Pages への公開は手動実行（`workflow_dispatch`）のときだけ行う（リポジトリが非公開で Pages を使えない間も push でワークフローが失敗しない）。既定の権限は `contents: read` だけで、`pages: write`・`id-token: write` は deploy ジョブにだけ与える。checkout は `persist-credentials: false`。秘密情報（secrets）は使わない。チェック（型チェック・テスト・ビルド）が成功したときだけ公開する。
- GitHub Pages ではレスポンスヘッダーを設定できないため、Content-Security-Policy は本番ビルドの `index.html` に meta タグで入れる（`vite.config.ts`。開発サーバーには入れない）。meta では `frame-ancestors` が効かないため、他サイトへの埋め込みは防げない。
- セーブデータは `localStorage` に保存され、オリジン（`https://taku5858.github.io`）ごとに分かれる。同じアカウントの他の Pages サイトとはオリジンが同じなので、キー名 `yaoya-pl-save-v2` が重ならないようにする。URL が変わると以前のセーブは引き継がれない。
- コミットの作成者情報（名前・メールアドレス）は、リポジトリを公開すると誰でも見られる。公開用リポジトリでは、最初のコミットから GitHub の noreply アドレスを使う（リポジトリ単位の `git config`）。
